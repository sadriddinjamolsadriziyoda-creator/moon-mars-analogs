# Происхождение данных

Как значение попало в `data/sites.json` и как его проверить.

## Файлы

| Файл | Что внутри | Кто читает |
|---|---|---|
| `data/sites.json` | 30 земных локаций | приложение, сервер, seed |
| `data/comparators.json` | 18 целей на Луне и Марсе | приложение, сервер, seed |
| `data/criteria.json` | 6 критериев: веса, допуски, описания | приложение, сервер, seed |

`data/sites.json` — источник истины, а не сборка. Файлы `sites-{mars,moon,central-asia}.json`
в том же каталоге — устаревшая черновая работа: другая схема slug
(`dallol-danakil` против `danakil-dallol`) и полные названия стран вместо ISO-кодов.
Они намеренно не читаются ни приложением, ни валидатором, ни seed-скриптом.
`scripts/build-catalog.ts`, который раньше их склеивал, отключён и выбросит ошибку.

## Схема одной локации

```jsonc
{
  "slug": "atacama-desert",           // стабильный идентификатор, ключ во всём
  "country": "CL",                    // ISO 3166-1 alpha-2, не полное название
  "center": [-69.5, -23.5],           // [lon, lat]
  "radiusKm": 60,                     // радиус описания локации
  "terrainType": ["desert", "acid-saline-lake"],
  "analogs": [
    {
      "body": "mars",                 // "mars" | "moon"
      "region": { "ru": "...", "en": "..." },
      "center": [-35.0, -20.0],
      "radiusKm": 300,
      "whySimilar": {
        "ru": "...",                  // 3–5 предложений, для читателя
        "detail": { "ru": "..." }     // научные детали, раскрываются по кнопке
      }
    }
  ],
  "features": {
    "relief": { "value": 0.86, "evidence": "high", "note": "по DEM Copernicus, 30 м" }
    // ... шесть критериев
  },
  "geologyMaterials": { "hematite": 0.7, "sulfate": 0.1, "basalt": 0.3, "clay": 0.05, "ilmenite": 0.2 },
  "missions": [ { "org": "NASA", "what": "...", "year": 2007, "url": "..." } ],
  "photos": [ { "src": "...", "credit": "...", "license": "CC BY-SA 4.0", "alt": { "ru": "..." } } ],
  "sources": [ { "title": "...", "org": "NASA", "url": "...", "accessed": "2026-10-04" } ],
  "confidence": "high",
  "reviewStatus": "verified"          // verified | needs-review
}
```

## `evidence` не входит в индекс

`evidence` (`high` / `medium` / `low`) **не** домножается на `sᵢ` и не влияет на балл.
Уверенность в данных ортогональна похожести: Атакама может быть очень похожа по климату
(обоснованно) и при этом иметь низкое инженерное сходство (оценка на глаз).

Смешивать их в одно число — ложная точность. На карточке оба показаны раздельно:
балл в счёте, уверенность — бейджем рядом с обоснованием.

## Правило источника

**Источник без работающей ссылки не принимается.** Не «примерно работающей» — работающей:
`npm run check-sources` читает начало тела ответа и ищет маркеры страниц ошибок, потому что
несколько хостов отвечают `200` с ошибкой в теле. Ссылка, которая выглядит рабочей,
но ведёт в никуда, хуже отсутствующей: она говорит «мы это проверили».

Скрипт завершается с ненулевым кодом при любой мёртвой ссылке — это CI-гейт.

## Требует научной проверки

Три локации помечены `reviewStatus: "needs-review"`:

| slug | Почему |
|---|---|
| `kaumana-caves` | мало опубликованных данных по солевому составу |
| `ust-yurt-plateau` | карта и литология расходятся между источниками |
| `dried-aral-bed` | уровень солёности быстро меняется, фиксировать нужно дату |

Они видны в приложении с явным бейджем, а не спрятаны. Спрятанное «needs-review»
выглядит как «verified» — это хуже, чем отсутствие локации.

## Что не сделано

- **Признаки не пересчитаны из DEM.** Значения в `features.*.value` — экспертная оценка
  по публикациям, а не результат питоновского пайплайна по Copernicus/MOLA/LOLA.
  Для каждого значения есть `note` со ссылкой на источник оценки. Воспроизводимый
  расчёт — в дорожной карте, не в MVP.
- **Климат не запрошен через NASA POWER автоматически.** Температура и осадки проставлены
  по справочным данным POWER для ближайшей точки. Автозагрузка по координатам —
  отдельная задача, требующая сети и кеша.
